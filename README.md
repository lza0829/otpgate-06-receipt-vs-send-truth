# 验码渠（Otpgate）

骨架：通道注册 → 选路投递 → 失败熔断切备通道 → 送达回执对账

- 前端 http://127.0.0.1:6900
- API http://127.0.0.1:11900
- 数据库环境变量 `OTPGATE_DB`（容器内默认 `/data/otpgate.db`）

```bash
docker compose up -d --build
```

## 送达结果真源（全局唯一）

**以回执簿送达事件重放为准**，全库只此一套，禁止两套长期并存：

- `receipts` 是只追加的送达事件流，带全局唯一 `seq`（送达序号）与幂等键；
  一笔送达是否终态、是送达还是失败，只由该流按序号倒序重放决定。
- `sends.status` 降级为**投影缓存**：每次回执写入在**同一笔事务**内
  「插回执 → 重放 → 刷投影（status / finished_at / deliver_seq / delivered_at）→ 记事件痕」，
  同成同败，不存在“回执成功而单态还停投递中”的半截。
- 数据库视图 `v_send_truth` 是唯一重放读模型。验码单终态、回执簿、路况已送达格、
  占用余量探针、轧差送达差额、事件痕全部从它取数；`送达与回执差` 恒为 0 即自洽。
- **缺回执不强造终态**：无回执单维持状态机原值并计入「缺回执待终结」；
  无回执却被强造的 `已送达` 会在重放纠偏中拉回。
- **纠偏位**：`POST /api/对账/纠偏重放` 全量重放，修一切半截拧花；启动时自动回填旧回执序号并重放。
- **手改 vs 补回执**：有回执的单手改一律拒绝（409），终态只听回执；
  无回执单仅可人工纠正到非送达态，不得手造已送达。
- 并发补回执靠库级写锁（`BEGIN IMMEDIATE` + busy_timeout）串行，序号不丢不重，长期只留一个终态。
- **晚到回执改写是独立准入策略**（渠规「回执晚到可改写」），只决定事件能否进日志，
  不改重放规则；关闭后晚到回执被拒、旧终态不动。
- 投递按钮、熔断切备是状态机旁路，只推进在途/失败态，不伪造回执、不参与送达裁决。
- 设置项「送达结果真源」为实现裁决，只读，任何改写请求返回 409。
